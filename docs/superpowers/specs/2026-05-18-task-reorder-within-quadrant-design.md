# Приоритизация задач внутри квадранта

Дата: 2026-05-18
Статус: утверждён

## Цель

Дать пользователю возможность вручную менять порядок задач (приоритизировать)
в пределах одного квадранта матрицы Эйзенхауэра. Верх списка = высший
приоритет.

## Решения, принятые при брейншторме

- **Взаимодействие:** drag-and-drop внутри квадранта с визуальным
  индикатором вставки. Единый паттерн с уже существующим переносом задач
  между квадрантами.
- **Размещение новой/перенесённой задачи:** вниз списка (низший приоритет).
  Касается как только что созданной задачи, так и задачи, перенесённой из
  другого квадранта.
- **Модель хранения порядка:** явное числовое поле `order` у задачи.

## Модель данных

В `src/types/task.ts` к интерфейсу `Task` добавляется поле:

```ts
order: number
```

`order` — порядковый индекс задачи **внутри своего квадранта**: `0, 1, 2 …`,
где `0` — верх списка (высший приоритет). Индексы держим компактными
(`0..n-1`) и пересчитываем при каждой перестановке, добавлении и переносе.
Дробная нумерация не используется — для небольших списков пересчёт проще и
детерминированнее.

## Чистая логика порядка

Новый модуль `src/storage/ordering.ts` — изолированные функции без
зависимости от Vue, юнит-тестируемые в принципе:

- `normalizeOrders(tasks: Task[]): Task[]`
  Приводит порядок в норму по каждому квадранту.
  - Если у всех задач квадранта есть числовой `order` — сортирует по `order`
    (стабильно) и переназначает `0..n-1`.
  - Если хотя бы у одной задачи квадранта `order` отсутствует (старые данные
    из `localStorage`) — сортирует задачи квадранта по `createdAt` по
    убыванию (новые сверху — текущий видимый порядок) и присваивает
    `0..n-1`.
  Это и есть разовая миграция старых данных без видимого пользователю
  скачка.

- `nextOrder(tasks: Task[], quadrant: QuadrantId): number`
  Возвращает `max(order)+1` среди задач указанного квадранта, либо `0`, если
  квадрант пуст.

- `reorderWithinQuadrant(tasks: Task[], quadrant: QuadrantId, draggedId: string, targetIndex: number): Task[]`
  Возвращает новый массив задач, в котором задача `draggedId` перемещена
  внутри `quadrant`, а `order` всех задач этого квадранта пересчитан в
  `0..n-1`. Задачи других квадрантов не изменяются.
  Семантика `targetIndex` (фиксируем во избежание классической ошибки
  off-by-one): задача `draggedId` сначала **удаляется** из упорядоченного
  списка квадранта, затем **вставляется** в позицию `targetIndex` уже
  усечённого списка (`targetIndex` в диапазоне `0..n-1`, где `n` — длина
  списка без перетаскиваемой задачи). Вызывающий код (обработчик
  `dragover`) обязан вычислять `targetIndex` в этих же терминах.

## Хранилище (`src/storage/taskStorage.ts`)

- `isValidTask`: поле `order` необязательно. Принимаем задачу, если `order`
  либо число, либо отсутствует (старые данные). Финальную нормализацию
  делает `normalizeOrders`, поэтому валидатор не обязан требовать `order`.
- `makeTask(title, quadrant, order)`: принимает готовое значение `order`.
  Вызывающий код вычисляет его через `nextOrder`.

## Компонент `src/components/EisenhowerMatrix.vue`

### Загрузка и миграция

`created()`: `loadTasks()` → `normalizeOrders(...)` → присвоить результат в
`this.tasks`. Существующий `watch` на `tasks` сразу запишет нормализованные
данные обратно в `localStorage`.

### Отображение

`tasksByQuadrant`: сортировка задач квадранта по `order` по возрастанию
вместо текущей сортировки по `createdAt`.

### Создание и перенос между квадрантами

- Создание задачи (`onPopoverSave`, режим `create`): `order =
  nextOrder(this.tasks, quadrant)` → задача уходит вниз своего квадранта.
- Перенос между квадрантами через поповер (`onPopoverMove`) и через
  cross-quadrant drop (`onDrop`, целевой квадрант ≠ исходный):
  `task.quadrant = target`, `task.order = nextOrder(this.tasks, target)` →
  задача уходит вниз целевого квадранта. Индекс точки сброса при переносе
  между квадрантами игнорируется (принятое решение, упрощает реализацию).

### Drag-and-drop внутри квадранта

- `dragstart` на карточке — `this.dragging = task.id` (уже существует).
- `dragover` на карточке задачи — вычисляем индекс вставки по положению
  курсора относительно вертикальной середины карточки (выше середины —
  вставка перед карточкой, ниже — после). Ставим
  `this.dropIndicator = { quadrant, index }` и рисуем линию-индикатор.
- `drop`:
  - тот же квадрант → `this.tasks = reorderWithinQuadrant(this.tasks,
    quadrant, this.dragging, index)`;
  - другой квадрант → поведение из раздела «Перенос между квадрантами»
    (вниз целевого).
- `dragend` — сброс `this.dragging`, `this.dropIndicator`, `this.dragOver`.

### Новое состояние компонента

`dropIndicator: { quadrant: QuadrantId; index: number } | null` — позиция
линии-индикатора вставки во время перетаскивания.

## Поведение и крайние случаи

- Перенос между квадрантами всегда кладёт задачу вниз целевого квадранта,
  даже если бросить точно между карточками.
- Бросок задачи на её же позицию (или эквивалентную) — no-op: порядок не
  меняется.
- Пустой квадрант — индекс вставки `0`.
- Touch-устройства: нативный HTML5 DnD на тач не работает. Это уже
  ограничение существующего переноса между квадрантами; отдельно в рамках
  этой задачи не решается.
- Перетаскиваемая карточка визуально приглушается (например, пониженная
  непрозрачность) на время drag.

## Верификация

Тест-раннера в проекте нет (скрипты: `serve`, `build`, `lint`).

- `yarn lint` — без ошибок.
- `yarn build` — без ошибок (включая проверку типов TS).
- Ручной чек-лист в браузере:
  1. Перетаскивание задачи вверх внутри квадранта меняет порядок.
  2. Перетаскивание задачи вниз внутри квадранта меняет порядок.
  3. Линия-индикатор вставки показывает корректную позицию при `dragover`.
  4. Порядок сохраняется после перезагрузки страницы.
  5. Новая задача появляется внизу своего квадранта.
  6. Задача, перенесённая из другого квадранта (поповер и DnD), появляется
     внизу целевого квадранта.
  7. Старые данные в `localStorage` без поля `order` открываются в текущем
     видимом порядке (новые сверху) без скачка и нормализуются.
  8. Бросок на ту же позицию ничего не ломает.

Чистые функции порядка изолированы в `src/storage/ordering.ts` — их можно
покрыть юнит-тестами, если позже в проект добавят тест-раннер. Добавление
тест-раннера в область этой задачи не входит (отдельная задача, осложнённая
ограничением TS 4.5 / Vue CLI).

## Затрагиваемые файлы

- `src/types/task.ts` — поле `order` в `Task`.
- `src/storage/ordering.ts` — новый модуль с чистой логикой порядка.
- `src/storage/taskStorage.ts` — `isValidTask` (order необязателен),
  `makeTask` (принимает order).
- `src/components/EisenhowerMatrix.vue` — загрузка/миграция, сортировка,
  создание/перенос, DnD внутри квадранта, новое состояние, стили
  индикатора.

## Вне области

- Тест-раннер и автотесты.
- Поддержка drag-and-drop на touch-устройствах.
- Дробная/разреженная нумерация `order`.
- Любой рефакторинг, не связанный с этой задачей.
